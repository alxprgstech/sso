# ADR 0017 — воспроизводимая CI-среда и изоляция тестовых сценариев

Дата: 04.10.2026. Статус: принято. Задача: PR5-CI-01.

CI run 37200621991 выявил накопление лимитов между независимыми сценариями,
отсутствие frontend-зависимостей в backend job и уязвимости старого Debian 12
образа. Защита приложения и обязательность проверок сохраняются.

Python runtime использует официальный `3.13.16-alpine3.24`, закреплённый
digest, проверенным в Docker Registry. Builder сохраняет инструменты сборки;
готовый образ содержит runtime lock, сертификаты и приложение. После установки
wheel удаляются ненужные pip/setuptools/wheel. curl и PostgreSQL client не нужны
серверному процессу: health использует стандартный urllib, а backup/restore
выполняются оператором с совместимыми инструментами PostgreSQL по инструкции.
Уязвимости проверяет прежний обязательный Trivy job без исключений HIGH/CRITICAL.
Первое обновление Debian12 → Debian13 в run37212573835 устранило CRITICAL,
но оставило45HIGH, в том числе upstream-unfixed util-linux/systemd/ncurses.
Поэтому выбран поддерживаемый минимальный Alpine с иной системной зависимостью,
а не подавление CVE. musl-совместимость locked wheels и криптографии должна
подтверждаться сборкой и реальным Compose-профилем того же CI. Этот результат
пока pending. [Официальные поддерживаемые теги](https://hub.docker.com/_/python).
Альтернатива — оставить устаревшую базу и подавить CVE — отклонена.

Backend job собирает настоящий frontend перед тестами жизненного цикла сервера.
PostgreSQL-тесты защиты БД исполняются в обязательном backend job; Windows job
выбирает только соответствующие платформе unit-регрессии через существующий
маркер. Отсутствие PostgreSQL в Windows job не становится skip в общей проверке.

pytest очищает процессный фильтр только на границе независимых тестов.
Passkey/TOTP browser beforeEach явно выбирает подготовку синтетических fixtures
с очисткой rate windows. Операция требует существующий валидный маркер
принадлежности тестовой БД; по умолчанию seed счётчики не очищает. Внутри каждого
сценария лимиты, одноразовость и replay-защита продолжают действовать. Увеличение
лимитов, сброс во время сценария и маскирующие retries отклонены.

Генератор session key отклоняет редкие случайные образцы, не соответствующие
неизменённой production-политике разнообразия символов. Для каждого образца
используются прежние 512 случайных бит из secrets; ослабления валидатора нет.

Проверки: новые регрессии квоты, отказа очистки без маркера, генератора и полноты
release build context; реальные PostgreSQL/browser/CI результаты записываются
после выполнения в журнал. Обновление digest само по себе не доказывает отсутствие CVE.
