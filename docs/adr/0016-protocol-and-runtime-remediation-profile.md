# ADR-0016 — Уточнённый протокольный и эксплуатационный профиль

> Сверка 06.10.2026: сохранено решение на дату принятия; это не новый результат приёмки. Действующий профиль: [архитектура](../architecture.md), [API](../api.md), [статус](../status.md).

Дата04.10.2026; принято для AUDIT-FIX-03/04/05. Решения сформулированы по фактически реализованному исправлению F-07…F-23. Их начало и проверки отмечены в worklog, этот документ не заменяет доказательства.

OP сохраняет Authorization Code + обязательный PKCE S256. `prompt=login`/`max_age=0` связывают новый login с точным запросом signed short-lived interaction cookie; last_activity не является authentication time. `prompt=none` даёт зарегистрированному callback protocol error и никогда не показывает UI. Scope policy хранится у клиента, применяется до выдачи code и к claims; roles и scopes независимы. Альтернативы implicit/hybrid, DCR, introspection, PAR, DPoP и back-channel logout не требуются подтверждёнными находками и не добавляются.

SDK проверяет ID Token и Access Token отдельными профилями, не импортирует сервер. Для `max_age=0` выделено фиксированное окно callback transit5 секунд с учётом integer NumericDate; это решение приложения, а не требование спецификации и не configurable unlimited leeway. OP всё равно требует новый login, nonce/state остаются обязательными в recommended flow. Возраст6 секунд отвергается. JWKS stream ограничен64KiB/16 валидными уникальными public RSA keys до cache; альтернативный неограниченный `get().json()` отвергнут как путь к resource exhaustion. Основание validation — [OIDC Core](https://openid.net/specs/openid-connect-core-1_0.html#IDTokenValidation).

Для общего default single-factor и enabled профилей выбраны15–128 Unicode символов, библиотечный Argon2id64MiB/t3/p4, единая политика без composition и periodic rotation. [NIST SP800-63B-4](https://pages.nist.gov/800-63-4/sp800-63b.html) используется как инженерное обоснование minimum/blocklist, не как сертификат или заявление AAL для всего продукта. Offline MIT SecLists subset сохраняет целые значения длиной15…128; короткие значения уже отвергаются minimum. Provider lookup не нужен и не раскрывает пароли наружу. Случайные recovery codes32A–Z/0–9 (≈165 бит) хешируются SHA-256 и атомарно погашаются только после пароля; Argon2 для высокоэнтропийного одноразового секрета не нужен. TOTP использует библиотечный [Fernet](https://cryptography.io/en/latest/fernet/#implementation), AES-128-CBC/HMAC-SHA256, а не ранее ошибочно описанный AES-256. При смене ключа ciphertext мигрирует транзакционно offline.

Runtime и migrations используют разные non-superuser PostgreSQL роли; runtime DML без schema ownership/DDL, migrator владеет application objects. Старый owner передаёт только известные tables/sequences/public schema при остановленном приложении, точной DB/owner identity и проверенных backup. `REASSIGN OWNED` на все объекты отвергнут: может затронуть чужие данные. Fresh init и previous upgrade подтверждаются PG drill; Linux entrypoint ещё требует mandatory container CI.

Production предусматривает одну TLS termination границу, точный Host и очистку forwarded headers у gateway, закрытый backend/DB. Uvicorn не доверяет произвольным proxy headers; source IP parser доверяет только явно заданным hops. Enforced CSP действует из внешнего Nginx config, без unsafe-inline/eval; Telemetry connection sources допускаются только точным ingest URL. На локальном Windows Nginx реальный Chromium проверяет те же директивы. Actual Linux images/rootfs/capabilities/resources/CVE и public HTTPS topology требуют отдельного execution evidence; статический Dockerfile не объявляется runtime PASS.
