# ALXPRGS Single Sign-On (SSO)

Закрытая программная система единого входа (Single Sign-On) и централизованной идентификации для экосистемы `alxprgs.tech`.

- **Целевой домен**: `alxprgs.tech`
- **Идентификатор поставщика (Issuer)**: `https://auth.alxprgs.tech`
- **Версия продукта**: `0.2.0` (SemVer, единый источник истины — `VERSION`)
- **Статус**: Готов к локальной эксплуатации и развёртыванию

---

## 1. Быстрый запуск (Быстрый старт)

Для запуска ALXPRGS SSO на рабочей станции требуются только установленный **Docker** с поддержкой **Compose** и штатная командная оболочка (PowerShell на Windows, Bash на Linux/macOS). Установка Python или Node.js на хост не требуется (SETUP-01).

### 1.1. Запуск одной командой

**Windows (PowerShell):**
```powershell
.\start.ps1
```

**Linux / macOS (Bash):**
```bash
chmod +x start.sh
./start.sh
```

### 1.2. Что выполняет мастер запуска

1. **Проверка окружения**: проверяет наличие `docker` в PATH, доступность демона Docker и доступность порта `127.0.0.1:3000` (TEST-SETUP-04).
2. **Безопасная конфигурация**: автоматически генерирует локальный файл `.env` с уникальными криптостойкими ключами (`SESSION_SECRET_KEY`, `TOTP_ENCRYPTION_KEY`, пароль БД) без перезаписи уже существующего файла (SETUP-04).
3. **Запуск сервисов**: поднимает изолированный контур Docker Compose (база данных PostgreSQL 16, бэкенд FastAPI, фронтенд Nginx + React).
4. **Проверка готовности**: ожидает успешного прохождения liveness healthcheck (`/health/live`) с контролем таймаута (до 60 секунд).
5. **Интерактивный мастер первого администратора (SETUP-03..SETUP-07)**:
   - Запрашивает логин администратора (по умолчанию: `admin`);
   - Запрашивает контактный email (по умолчанию: `admin@alxprgs.tech`);
   - Запрашивает пароль администратора со **скрытым вводом в терминале** (`getpass`) и обязательным подтверждением (минимум 8 символов);
   - Предлагает выбрать режим самостоятельной регистрации обычных пользователей:
     - `[1] closed` (закрытый режим, рекомендуется по умолчанию);
     - `[2] open` (открытый режим со свободной регистрацией).
6. **Готовность**: выводит ссылки на интерфейс и открывает браузер.

Адреса сервисов:
- Пользовательский интерфейс и шлюз: `http://localhost:3000` (привязка строго к `127.0.0.1:3000`, SETUP-08);
- Панель администратора: `http://localhost:3000/admin`;
- База данных PostgreSQL: порт 5432 **не публикуется наружу** для защиты корпоративных данных (SETUP-08).

### 1.3. Повторный запуск и идемпотентность (SETUP-05, SETUP-06)

Повторное выполнение `.\start.ps1` или `./start.sh`:
- Не перезаписывает существующий `.env` и секреты;
- Не сбрасывает базу данных и созданных пользователей;
- Не запрашивает повторный ввод пароля администратора и завершается со статусом 0;
- При наличии существующего обычного пользователя мастер отказывает в автоматическом повышении прав (SETUP-06).

Резервная команда ручного запуска мастера внутри контейнера:
```bash
docker compose exec -it backend python -m app.cli.bootstrap_admin
```

## 2. Архитектура и функциональные возможности

### 2.1. Регистрация и управление режимом (REG-01..REG-09)
- **Открытый режим (`open`)**: на странице входа отображается ссылка на форму регистрации (`RegisterPage.tsx`), позволяющая создать учётную запись обычного пользователя (`ROLE_USER`).
- **Закрытый режим (`closed`)**: по умолчанию при первой установке и обновлении существующих инстансов. API блокирует создание пользователей (HTTP 403), интерфейс скрывает ссылку на регистрацию.
- **Управление из панели администратора**: администратор может переключать режим в реальном времени на вкладке «Конфигурация» с обязательным подтверждением текущего пароля администратора (re-auth, REG-02). Изменение немедленно вступает в силу для всех процессов без перезапуска.
- **Безопасность регистрации**: защита от коллизий без раскрытия полей (HTTP 409), строгая запрещающая схема (`extra="forbid"`), межпроцессный rate limiting через аудит PostgreSQL и скользящее окно в памяти, валидация Origin/CSRF.

### 2.2. Сервер аутентификации и OIDC Provider (`backend/`)
- FastAPI + PostgreSQL 16 + SQLAlchemy 2.0 (драйвер `psycopg`);
- Хеширование паролей Argon2id (RFC 9106);
- OpenID Connect Core 1.0 Provider:
  - Discovery (`/.well-known/openid-configuration`), JWKS (`/jwks.json`);
  - Authorization Code Grant с обязательным PKCE S256 (RFC 7636);
  - Выпуск RS256 JWT Access Token (5 мин) и ID Token;
  - Ротация Refresh Token с детектированием Replay (Token Family Replay Detection, SSO-05);
  - Эндпоинт UserInfo (принимает только Bearer Access Token);
  - Отзыв токенов (RFC 7009) и RP-initiated Logout;
- Защита от перечисления пользователей при входе;
- Серверный RBAC с разграничением прав суперпользователя и защитой последнего администратора (USR-08).

### 2.3. Пользовательский веб-интерфейс (`frontend/`)
- React 18, TypeScript, Vite, Tailwind CSS;
- Страница входа с адаптивной поддержкой OIDC-параметра `return_to`;
- Страница самостоятельной регистрации (`RegisterPage.tsx`);
- Личный кабинет: профиль, смена пароля, мониторинг и мгновенный отзыв активных сессий;
- Панель администратора: управление пользователями, регистрация OIDC-клиентов с однократным показом секрета (USR-09), журнал аудита в реальном времени, управление режимом регистрации.

### 2.4. Python SDK `alxprgs-sso` (`packages/python-sdk/`)
- Полная изоляция от внутренних модулей сервера (раздел 3 AGENTS.md);
- Кэширование JWKS с TTL и криптографическая проверка RS256 токенов;
- Интеграция с FastAPI (`SSOFastAPISecurity`, зависимости `get_current_user`, `require_role`);
- Два демонстрационных клиента в `examples/client1` и `examples/client2`, демонстрирующих бесшовный SSO.

## 3. Обязательные инварианты и флаги отложенных возможностей

В соответствии с требованиями `GOAL.md`, `GOAL-02` и `AGENTS.md`, функционал многофакторной аутентификации и подтверждения почты **полностью программно реализован**, но **жестко отключен по умолчанию** во всех поставляемых конфигурациях:

```env
FEATURE_TOTP_ENABLED=false
FEATURE_PASSKEY_ENABLED=false
FEATURE_RECOVERY_CODES_ENABLED=false
FEATURE_EMAIL_VERIFICATION_ENABLED=false
REQUIRE_VERIFIED_EMAIL=false
```

- При выключенных флагах эндпоинты TOTP, Passkey, Recovery codes и Email verification возвращают HTTP 404 (`feature_disabled`);
- Фоновые рассылки писем не производятся (`sent_emails_sink`);
- В default-профиле учетные записи администраторов и зарегистрированных пользователей создаются с `email_verified=False`;
- При включении тестового профиля `REQUIRE_VERIFIED_EMAIL=true` неподтвержденная учетная запись блокируется до верификации токена.

## 4. Тестирование и верификация

### 4.1. Автоматизированные тесты pytest (54 теста)

```bash
# Запуск полного тестового набора по всем 11 модулям:
pytest tests/ -v
```

Тестовый комплект покрывает:
- OIDC Protocol: PKCE S256, Authorization Code, Token, UserInfo, Refresh Token Replay Detection;
- Регистрация и управление режимом (`tests/test_registration.py`, 12 тестов): открытый/закрытый режим, коллизии, запрет повышения прав, rate limiting, изоляция email;
- Мастер первого запуска (`tests/test_bootstrap_admin.py`, 7 тестов): первичная инициализация, идемпотентность, отказ в повышении прав обычного пользователя, валидация TTY;
- Отложенные возможности (`tests/test_mfa_features.py`): изоляция default-off и корректность enabled-профиля;
- Административный API и RBAC (`tests/test_admin_api.py`);
- Python SDK и кросс-сервисный SSO (`tests/test_python_sdk.py`, `tests/test_sso_cross_clients.py`);
- Негативные сценарии безопасности и гонки (`tests/test_security_and_negative_scenarios.py`).

### 4.2. Проверка фронтенда

```bash
cd frontend
npm run typecheck
npm run build
```
