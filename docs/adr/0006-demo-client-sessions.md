# ADR-0006 — серверные сессии демонстрационных OIDC-клиентов

- Дата: 2026-09-26. Статус: принято для демонстрационных клиентов GOAL-09 / C9-02.

## Решение

Каждый пример хранит flow и web-сессии в памяти своего единственного процесса (`examples/demo_sessions.py`). Браузер получает только случайные непрозрачные идентификаторы в host-only HttpOnly cookie. Flow погашается при первом callback, имеет TTL 300 с и сверяет state. Web-сессия имеет абсолютный TTL 24 часа, idle TTL 1 час и отдельный CSRF token для POST logout. Идентификатор выпускается заново после успешного OIDC callback; cookie не содержит claims или токенов. Все ID/access/refresh токены остаются в серверной памяти и исчезают при завершении процесса.

Локальный HTTP допускается только при явном `DEMO_ALLOW_HTTP_LOCALHOST=1`. В остальных случаях session cookie требует HTTPS; production с несколькими workers **не поддерживается** этим примером. Масштабируемый клиент должен заменить process-local store на общее серверное хранилище с атомарным погашением flow, TTL и отзывом. SDK не зависит от backend.

## Причина и альтернативы

Ранее подписанная cookie с известным ключом и бессрочными доверенными claims позволяла подделать сессию. Для демонстрации одного процесса память достаточна и сразу показывает отзыв и истечение. PostgreSQL/Redis для двух коротких примеров добавили бы эксплуатационный сервис; отдельное решение требуется перед многопроцессным или production запуском. Подписанные клиентские claims отклонены: сервер не может гарантировать немедленный отзыв и idle TTL.

## Проверки и пределы

Требуются unit/HTTP тесты неизвестного ID, TTL, replay, CSRF, чужого браузера, escaping и рестарта. Реальный browser E2E с установленным wheel и двумя отдельными процессами обязателен до C9-02/03 `done`. Запуск этих проверок на текущем дереве ещё не выполнен.
