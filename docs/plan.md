## 1. Общие принципы планирования

1. Задачи имеют стабильные идентификаторы вида `TASK-XXX`.
2. Статусы задач: `planned`, `in_progress`, `blocked`, `done`, `cancelled`.
3. Переход в статус `done` разрешён только при выполнении критерия готовности и прохождении обязательных проверок.
4. Отложенные возможности (`FEATURE_TOTP_ENABLED`, `FEATURE_PASSKEY_ENABLED`, `FEATURE_RECOVERY_CODES_ENABLED`, `FEATURE_EMAIL_VERIFICATION_ENABLED`) должны быть полноценно реализованы, проверены в enabled-профиле и жестко отключены по умолчанию.

## 3. Детализация критериев готовности задач

### TASK-001: Создание системы трекинга разработки
- **Критерий готовности**: Созданы `docs/plan.md`, `docs/worklog.md`, `docs/status.md`, `GOAL.md`. Документы соответствуют требованиям DOC-TRACK-01..07.

### TASK-002: Архитектурное проектирование
- **Критерий готовности**: Созданы документы `docs/architecture.md`, `docs/data-model.md`, `docs/security.md`, `docs/standards-profile.md`, ADR в `docs/adr/`. Описаны структуры сущностей, потоки OIDC/MFA, модель угроз.

### TASK-003: Система версионирования и CI/CD
- **Критерий готовности**: Созданы корневой `VERSION`, скрипт синхронизации версий `scripts/bump-version.py`, `CHANGELOG.md`, `docs/releases.md`, `.github/workflows/ci.yml`, `.github/workflows/release.yml`, закомментированный шаблон `deploy/github-actions/cd.yml.example`.

### TASK-004: Каркас FastAPI бэкенда и БД
- **Критерий готовности**: Структура бэкенда с разделением API/core/services/models, конфигурация `pydantic-settings` с флагами по умолчанию `false`, модели SQLAlchemy, миграции Alembic, CLI-команда инициализации первого администратора.

### TASK-005: Ядро аутентификации и сессий
- **Критерий готовности**: Хеширование Argon2id, управление серверными сессиями в PostgreSQL, host-only secure cookies, защита от CSRF, журнал событий аудита.

### TASK-006: OIDC-провайдер
- **Критерий готовности**: Рабочие эндпоинты `/.well-known/openid-configuration`, `/jwks.json`, `/oauth/authorize`, `/oauth/token`, `/oauth/userinfo`, `/oauth/revoke`, `/oauth/logout`. Поддержка PKCE S256, ротация refresh token, детектирование replay.

### TASK-007: Отложенные возможности (MFA & Email)
- **Критерий готовности**: Полная реализация TOTP (шифрование секретов), Passkey (WebAuthn credentials, challenges), Recovery codes (хеши, атомарное сгорание), Email verification (токены, mock/SMTP адаптер). Проверено: при `false` все эндпоинты возвращают 404/feature_disabled.

### TASK-008: REST API кабинета и админки
- **Критерий готовности**: Эндпоинты профиля, смены пароля, сессий, управления пользователями, клиентами OIDC, ролями, журналом аудита. Серверный RBAC.

### TASK-009: Фронтенд на React + TypeScript
- **Критерий готовности**: React-приложение: экран входа, профиль, MFA-настройки (при enabled), админ-панель (пользователи, клиенты, аудит). Сборка проходит без ошибок, типизация строгая.

### TASK-010: Python SDK и примеры клиентов
- **Критерий готовности**: Пакет `packages/python-sdk` (`alxprgs-sso`) с `pyproject.toml`, FastAPI dependency проверки bearer токена, helper для web login. Два примера приложений в `examples/client1` и `examples/client2`.

### TASK-011: Комплексные тесты
- **Критерий готовности**: Pytest unit + integration тесты на PostgreSQL, негативные тесты OIDC, тесты изоляции флагов возможностей, WebAuthn виртуальный аутентификатор, тесты гонок.

### TASK-012: Эксплуатационный контур
- **Критерий готовности**: `docker-compose.yml` для полного запуска системы, скрипты резервного копирования и восстановления PostgreSQL, ротации ключей, `docs/operations.md`.

### TASK-013: Комплект документации ЕСПД
