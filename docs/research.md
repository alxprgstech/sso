## 1. Контекст и исследовательские цели

Программный комплекс ALXPRGS SSO разработан с возможностью применения в научных исследованиях в области информационной безопасности, систем распределенной идентификации и протоколов единого входа (OIDC/OAuth 2.0).

Основными направлениями научных исследований являются:
1. Анализ устойчивости протокольных реализаций OpenID Connect к атакам воспроизведения (Replay Attacks) при ротации токенов и обмене кодов авторизации;
2. Сравнительный анализ задержек аутентификации при использовании парольного входа (Argon2id RFC 9106) и аппаратных ключей WebAuthn / Passkeys (FIDO2 / W3C Level 3);
3. Моделирование конкурентных гонок (Race Conditions) при параллельном погашении одноразовых авторизационных артефактов в реляционных транзакционных средах;
4. Оценка накладных расходов криптографической валидации распределенных токенов (RS256 JWT) с кэшированием JWKS по сравнению с централизованной интроспекцией (RFC 7662).

## 3. Методика проведения экспериментов

### 3.1. Исследование криптографической стойкости Argon2id
- **Параметры эксперимента**:
  - Алгоритм: Argon2id (RFC 9106);
  - Объем памяти: 64 МБ (`m=65536`);
  - Количество итераций: 3 (`t=3`);
  - Параллелизм: 4 потока (`p=4`).
- **Синтетический сценарий**: Замер времени вычисления хеша и времени сверки пароля на фиксированном процессорном ядре при различной нагрузке.

### 3.2. Моделирование атак Replay на семейство токенов (Token Family)
- **Сценарий**:
  1. Выпуск начального Refresh Token $RT_0$ для клиента;
  2. Легитимная ротация $RT_0 \to RT_1$; токен $RT_0$ помечается в базе данных как `is_revoked=True`;
  3. Имитация перехвата $RT_0$ злоумышленником и отправка запроса на эндпоинт `/oauth/token`;
  4. Фиксация реакции сервера: немедленное аннулирование всех токенов семейства (`family_id`), запись инцидента `refresh_token_replay_detected` в аудит безопасности, возврат HTTP 400 `invalid_grant`.
- **Контролируемый критерий**: Ни один токен из скомпрометированного семейства не может быть использован для получения нового Access Token.

### 3.3. Моделирование гонок при конкурентном погашении кодов авторизации
- **Сценарий**:
  - Параллельная отправка $N$ ($N \in [2, 100]$) одновременных асинхронных запросов на обмен одного и того же Authorization Code.
  - Оценка транзакционной изоляции PostgreSQL: ровно один запрос должен завершиться успешным выпуском токенов ($200\text{ OK}$), остальные $N-1$ запросов должны быть отклонены сервером ($400\text{ Bad Request}$, `invalid_grant`).

## Ограничения сравнений

Introspection — внешний comparator: endpoint RFC 7662 в текущем SSO отсутствует. Эксперимент требует отдельного описанного синтетического стенда. Измерения не разрешают ослаблять replay/races; каждый прогон сохраняет SHA и окружение.
