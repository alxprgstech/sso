# ADR 0003: Выбор библиотеки реализации WebAuthn / Passkey

- **Статус**: Принято
- **Дата**: 2026-09-24T11:38:00+03:00
- **Исполнитель**: Antigravity

## Контекст

Требования `FEATURE_PASSKEY_ENABLED`, SEC-FLAG-06 и инварианты безопасности требуют:
- Полноценную реализацию WebAuthn Level 3: регистрация, вход и удаление нескольких credentials.
- Проверку origin, RP ID (`auth.alxprgs.tech`), user verification, challenges.
- Корректную обработку синхронизируемых Passkeys (Multi-device credentials), где `sign_count` не обязан монотонно возрастать (в отличие от физических USB-токенов).
- Проверку в тестах с использованием виртуального аутентификатора.

## Решение

Использовать официальную библиотеку **`webauthn`** (py_webauthn от Duo Security / Cisco, лицензия BSD-3-Clause):
- Полное соответствие спецификации W3C Web Authentication Level 3.
- Готовые функции генерации challenge, проверки attestation и assertion.
- Поддержка параметров `user_verification="preferred"` / `"required"`, типов транспортов (`internal`, `usb`, `ble`, `nfc`, `hybrid`).
- Поддержка современных Passkeys с учетом нюансов синхронизации счетчиков подписи.

## Альтернативы

- *Собственный парсер CBOR / COSE*: недопустимо согласно правилу запрета собственных криптографических реализаций.
- *fido2*: библиотека от Yubico ориентирована в первую очередь на создание клиентских устройств (аутентификаторов) и низкоуровневую работу по USB/HID, в то время как `webauthn` оптимизирована для серверной стороны (Relying Party).

## Последствия

- Надежная защита от атак повторного воспроизведения challenges.
- Возможность эмуляции виртуального аутентификатора в Playwright и pytest для тестирования сквозных сценариев.
