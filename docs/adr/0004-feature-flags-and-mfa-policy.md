# ADR 0004: Управление флагами отложенных возможностей и политика MFA

- **Статус**: Принято
- **Дата**: 2026-09-24T11:38:00+03:00
- **Исполнитель**: Antigravity

## Контекст

По прямому требованию ТЗ (`GOAL.md` раздел 3.3, 5, `AGENTS.md` раздел 5):
- Четыре возможности: **TOTP**, **Passkey**, **Recovery codes**, **Подтверждение почты** должны быть реализованы на 100% (БД, API, бизнес-логика, фронтенд, тесты), но в поставляемой конфигурации по умолчанию **все четыре строго отключены** (`false`).
- Требуется исключить фиктивные заглушки и обеспечить невозможность включения функций со стороны клиента или через манипуляции с браузером.
- Недопустимы ситуации скрытого обхода (bypass) защиты.

## Решение

1. **Серверные переменные окружения**:
   - `FEATURE_TOTP_ENABLED: bool = False`
   - `FEATURE_PASSKEY_ENABLED: bool = False`
   - `FEATURE_RECOVERY_CODES_ENABLED: bool = False`
   - `FEATURE_EMAIL_VERIFICATION_ENABLED: bool = False`
   - `REQUIRE_VERIFIED_EMAIL: bool = False`
   Значения по умолчанию в классе `Settings` жестко зафиксированы в `False`.

2. **Защита API и принцип Fail-Closed**:
   - Специальный FastAPI dependency `require_feature(flag_name)` устанавливается на уровне роутеров соответствующих модулей.
   - Если флаг выключен, запрос немедленно прерывается со статусом `HTTP 404 Not Found` и телом `{"error": "feature_disabled", "detail": "Requested feature is disabled by server configuration"}`.
   - Это гарантирует, что атакующий не может даже определить наличие или структуру отключенных эндпоинтов.

3. **Валидация зависимостей конфигурации (Startup Invariants)**:
   - При старте приложения Pydantic validator проверяет:
     - `FEATURE_RECOVERY_CODES_ENABLED` не может быть `True`, если `FEATURE_TOTP_ENABLED` равен `False`.
     - `REQUIRE_VERIFIED_EMAIL` не может быть `True`, если `FEATURE_EMAIL_VERIFICATION_ENABLED` равен `False`.
   - При нарушении приложение аварийно завершает запуск с информативным сообщением об ошибке конфигурации.

4. **Предотвращение MFA Bypass**:
   - Если пользователь ранее привязал TOTP или Passkey в тестовой среде, а затем флаг был отключен администратором, вход с паролем блокируется до прохождения административной процедуры сброса факторов, исключая несанкционированное понижение класса защиты.

5. **Изоляция почтовых отправлений**:
   - Отправка email абстрагирована интерфейсом `EmailSender`. При `FEATURE_EMAIL_VERIFICATION_ENABLED = False` почтовый сервис даже не инициализирует SMTP-соединения. Для тестов используется локальный in-memory/mock почтовый сборщик.

## Последствия

- 100% соблюдение требований SEC-FLAG-01..07.
- Чистое тестирование: переключение профилей осуществляется исключительно передачей переменных окружения тестового раннера (`TEST_PROFILE=enabled`).
