# ADR 0018: разделение проверок безопасности без изменения политики

> Сверка 06.10.2026: сохранено решение на дату принятия; это не новый результат приёмки. Действующий профиль: [архитектура](../architecture.md), [API](../api.md), [статус](../status.md).

Дата: 2026-10-04. Статус: принято. Задача: PR5-CI-01.

CodeScene выявил сложные функции проверки токенов, конфигурации, входа и MFA.
Такая структура затрудняла сопоставление отдельных защитных условий с тестами.

Проверки разделяются по границам доверия: структура claims, времена, audience,
профиль токена; пароль, политика факторов, одноразовый MFA-шаг; привязка logout,
подтверждение формы и CSRF. Порядок блокировок и фиксации транзакций сохраняется.
Кэш JWKS использует общие функции для синхронного и асинхронного транспорта,
с прежними пределами ответа, TTL, stale-интервалом и частотой обновления.

TOTP, recovery codes и криптографические проверки WebAuthn выделяются в отдельные
используемые модули. Публичные импорты из mfa_service сохраняются. Независимый SDK
не импортирует сервер. Объекты запроса и доказательства содержат связанные поля,
а действующий пользователь и сессия передаются вместе; API-контракты сохраняются.

Тестовые помощники объединяют параметры запроса и его авторизации, сохраняя
реальные password/MFA-проверки и отрицательные случаи. Контейнерный сценарий
разделён на подготовку, проверки, отказ БД и очистку строго своих ресурсов.

Альтернативы: оставить длинные функции; исключить файлы или подавить замечания
CodeScene. Выбрано разделение функций с повторной криптографической, PostgreSQL
и браузерной регрессией. Исключения, ослабление проверок и изменение порогов
анализатора не применяются. Исходные снимки аудита сохраняются побайтно.
