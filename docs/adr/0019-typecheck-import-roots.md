# ADR 0019: проверка реальных типов внутренних модулей

Дата: 2026-10-04. Статус: принято. Задача: PR5-CI-01.

Дополнительный запуск mypy с корнями backend и packages/python-sdk выявил
расхождения, которые прежняя команда скрывала за Any во внутренних импортах.
При explicit-package-bases имя модуля зависит от корня поиска; отсутствие
нужного корня снижает достоверность проверки. Это описано в
[официальной документации mypy](https://mypy.readthedocs.io/en/stable/running_mypy.html).

Корни задаются в локальном mypy.ini, используемом существующей обязательной
CI-командой. Регрессия импортирует настоящий User и проверяет отказ присваивания
его UUID переменной int. Не добавляются ignores для внутренних типов.

Общие временные поля выделяются в TimestampedBase, UUID id остаётся в Base.
SystemConfiguration наследует временные поля и объявляет собственный int id.
Используются одна registry и тот же объект metadata. Схема и миграции не меняются;
это проверяется настоящим migration/drift/role drill на PostgreSQL.
Абстрактные классы поддержаны
[SQLAlchemy Declarative](https://docs.sqlalchemy.org/en/20/orm/declarative_config.html).

Optional значения сужаются после проверки: hostname production, request ID,
тип времени взаимодействия OIDC. Дата согласия не выдумывается: отсутствующая
дата приводит к структурированному отказу и откату регистрации.

Альтернативы: оставить внутренние импорты динамическими, добавить type: ignore
или изменить схему singleton. Они не решают достоверность проверки либо
необоснованно меняют данные. Выбраны точные типы и проверки существующей схемы.
