# ADR 0002: Выбор протокольной библиотеки реализации OpenID Connect и OAuth 2.0

- **Статус**: Принято
- **Дата**: 2026-09-24T11:38:00+03:00
- **Исполнитель**: Antigravity

## Контекст

Требования SSO-01..08 и AGENTS.md устанавливают жесткие правила:
- Реализовать согласованный профиль OpenID Connect: Discovery, JWKS, Authorization Code с PKCE S256, Token, UserInfo, Revocation, Logout.
- Запрещено использовать самодельные криптографические алгоритмы или считать простую генерацию JWT достаточной для SSO.
- Стандартные FastAPI OAuth2 helpers (`OAuth2PasswordBearer`) реализуют лишь схему Swagger UI и проверку заголовков, но не являются OIDC-провайдером.
- Библиотека должна быть поддерживаемой, активно обновляемой и иметь лицензию, совместимую с закрытым проектом (BSD / MIT / Apache 2.0).

## Решение

Использовать комбинацию проверенных библиотек:
1. **Authlib** (BSD-3-Clause):
   - Индустриальный стандарт в экосистеме Python для построения OAuth 2.0 и OpenID Connect серверов.
   - Поддерживает Authorization Code Grant, PKCE (RFC 7636, метод `S256`), генерацию ID Token с соблюдением требований OpenID Connect Core 1.0, Token Revocation (RFC 7009).
   - Предоставляет спецификацию валидации `redirect_uri`, `scope`, `nonce`, `client_id` и аутентификации клиентов.
2. **cryptography** (Apache-2.0 / BSD):
   - Генерация и управление RSA-ключами (2048 бит), экспорт публичных ключей в формате JWK / JWKS с идентификаторами `kid`.
   - Защищенные криптографические операции.
3. **PyJWT** (MIT):
   - Высокопроизводительное декодирование и автономная верификация токенов в Python SDK (`alxprgs-sso`).

## Альтернативы

- *Собственная реализация протокола с нуля на FastAPI*: категорически запрещено инвариантом «Не реализуй собственные алгоритмы и не считай наличие JWT достаточным для SSO». Приводит к скрытым уязвимостям в валидации протокола (порядок проверки state, timing attacks, replay attacks).
- *python-oauth2*: устарела, не поддерживает современные стандарты OIDC и PKCE.
- *oauthlib*: широко известна, однако поддержка OpenID Connect требует громоздких адаптеров; Authlib предоставляет более цельную модель для современных ASGI фреймворков.

## Последствия

- Полная совместимость со спецификациями RFC 6749, RFC 7636, OIDC Core 1.0.
- Возможность точной интеграции с моделями PostgreSQL для атомарного погашения кодов и ротации refresh токенов.
